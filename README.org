#+TITLE: compoje - docker swarm templates

Using Docker compose file spec for Docker Swarm deployment lacks some features.
Hence this project.

- Docker swarm assumes a smart client - provides a basic set of features.
  More advanced functionality is expected to be implemented by smart clients.
- Secrets and configurations are immutable.
  Swarm deploy will fail if you change and redeploy a secrets with the same name.

** How it works

New to compoje? Start with the [[file:docs/quick-start.md][quick start guide]].
Still using compoje.edn? See [[file:docs/migrate-from-compoje-edn.md][migrating from compoje.edn]].

For all documentation see [[file:docs/README.md][docs/README.md]]: CLI, configuration, templates and secret providers.

** Features

Docker compose files don't support features that *compoje* tries to solve:

*** Docker configs and Docker secrets that change

Secrets and configs in Docker are immutable.
This makes change management tricky.
*compoje* solves this issue by creating configs and secrets names
that include the content hash in the name.

When you change the file contents the hash will change.
This causes a new config/secret to be added and used in the service.

Periodically, you will have to clean unused configs/secrets.

*** Template values in stack defintions

Docker supports interpolation from environment variables.
This is nice but sometimes not the best option.

*compoje* allows you to use values loaded from files, cli args or other providers.

** Installation and running

compoje runs on [[https://babashka.org/][babashka]]. Quick install, one line (installs a =compoje= command in =~/.local/bin=):

#+BEGIN_SRC shell
bb -e '(load-string (slurp "https://raw.githubusercontent.com/ieugen/compoje/main/install.clj"))'
#+END_SRC

Other ways to install it, all described in [[file:docs/install.md][docs/install.md]]:

- as a task in your project's *bb.edn*, pinned to a release tag (recommended for repositories with stacks)
- as a global =compoje= command with [[https://github.com/babashka/bbin][bbin]]
- as =compoje.jar= from the [[https://github.com/ieugen/compoje/releases][GitHub releases]], which needs only bb (good for CI)

#+BEGIN_SRC clojure
;; bb.edn
{:deps {io.github.ieugen/compoje {:git/tag "v0.2.0" :git/sha "abc1234"}}
 :tasks {:requires ([compoje.cli :as cli])
         compoje {:doc "Run compoje."
                  :task (apply cli/main *command-line-args*)}}}
#+END_SRC

#+BEGIN_SRC shell
# display help (also works per command: bb compoje deploy --help)
bb compoje --help

# Create a new stack directory with a working example
bb compoje init my-stack

# Render and show the stack and the docker command, without deploying
bb compoje deploy --dry-run example-stacks/nginx/stack.tpl.yml

# Deploy a stack, overriding the stack name from the file
bb compoje deploy --stack my-stack example-stacks/nginx/stack.tpl.yml
#+END_SRC

See the [[file:docs/quick-start.md][quick start guide]] for a full walk-through, and [[file:docs/releasing.md][docs/releasing.md]] for how releases are made.

** Roadmap

Still to do, in order (details in [[file:docs/known-issues.md][docs/known-issues.md]] where noted):

- [ ] Deprecate the provider =local-path= option (it writes secrets to disk); =compoje migrate= already converts it
- [ ] Known issues: render the stack file that was passed instead of always =stack.tpl.yml=; the HashiCorp Vault
  provider should throw instead of exiting the process

Done or dropped:

- Render, dry run, deploy, =--set= values, HashiCorp Vault, ansible-vault and file providers, documentation and
  examples, the =to-yaml= tag, installation via bb, bbin and a one-line installer.
- Validating the =x-compoje= configuration (malli): unknown keys with "did you mean", provider references, reserved
  secret names ([[file:docs/configuration.md][docs/configuration.md]]).
- Scaffolding a new stack: =compoje init <dir>= ([[file:docs/cli.md][docs/cli.md]]); replaces the old "stack
  initialization with compoje.edn" item.
- Escaping secret values in templates: the =escape-dollar= and =yaml-str= filters
  ([[file:docs/templates.md][docs/templates.md]]).
- Deploying without the docker client: the =docker-api= engine ([[file:docs/engines.md][docs/engines.md]]).
  contajners was considered and not used: it has no SSH transport and shells out to curl on babashka.
- Keeping secrets after render: secrets no longer need files (=x-compoje: {from: ...}=), see
  [[file:docs/security.md][docs/security.md]].
- Supporting the Compose Specification: =docker stack deploy= has its own compose schema and rejects newer
  compose-spec keys; compoje passes the file through (=docker-cli=) or supports a documented subset (=docker-api=).
